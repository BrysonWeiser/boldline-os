**Why they exist:** `createCampaign` on Meta hard-fails without an image, and the Meta App Review path (KB `meta-marketing-api`) needs real ads actually delivering on the house account for 15+ days. Bryson asked for images he could upload rather than sourcing stock.

**HARD RULE #1 — NO DRAWN BUTTONS (Bryson, 2026-08-12: "the images need to work for the meta ads not having a visual where the button doesn't work").** The first pass painted a gold "Book a 30-minute call" pill into the creative. Wrong on two counts: the real CTA on a Meta ad is the **platform's own button underneath the image**, so a pill inside the image is dead pixels that a user will tap and nothing happens; and Meta's ad policy prohibits **non-functional buttons and elements that mimic platform UI**. Replaced with a footer that has no button affordance at all — a gold hairline rule, then `boldlinemedia.com` in gold and the offer as plain text ("Free 30-minute strategy call"). Same rule applies to any future creative: **no pills, no rounded rectangles, no drop shadows, no play/like/checkbox glyphs.** The image carries the hook; the CTA belongs to the ad, not the artwork.

**HARD RULE #2 — no invented proof.** BoldLine has zero clients as of 2026-08-12, so every line is a claim about *what the service is or how it works*, never about results it has produced. No "we generated X leads", no star ratings, no testimonials, no client logos, no fabricated case-study numbers. That would be both false and the kind of thing Meta rejects. Also **no emojis** — these are the most client-facing surface there is (standing rule, KB `client-email-center`).

**The seven angles:**

|---|---|---|
| `top-of-google` | "Your competitors are **buying the top of Google**." | Competitive loss aversion — the strongest cold opener |
| `phone-ringing` | "Ads that make **the phone ring**." | Outcome in the prospect's own language |
| `not-a-website` | "A website tells them you exist. **A landing page makes them call**." | Sells the landing-page half, which is the differentiator |

| `niche-hvac` | "**HVAC:** own the searches that matter." | Named-niche; intent framing |

**City-targeted roofing set (2026-08-12)** — 5 cities (Gilbert, Chandler, Phoenix, Mesa, Tempe) × 3 angles × 3 sizes = 45 files, `roofing-<city>-<angle>--WxH`:
- **`shared-leads`** — "{City} roofers: stop buying shared leads." The sharpest pain in roofing; a lead resold to four competitors is a universally hated experience.
- **`be-first`** — "When {City} searches for a roofer, be the name they see."
- **`storm-season`** — "Storm season sends {City} straight to Google." Timed to Arizona monsoon (roughly June–September) — generated mid-August, so it is in season on arrival. Rotate it out in autumn.

Named cities beat "Arizona": a Gilbert roofer scrolling past the word *Gilbert* stops in a way they never do for a regional ad. These pair directly with Lead Scout's Gilbert/Phoenix HVAC + roofing runs — same targets, warmed by the ad before the cold call. Add a city by appending to `CITIES` in the script.

Niche-first beats generic — swap the niche word and rebuild for each vertical Lead Scout is targeting. All CTAs point at a 30-minute call (the Calendly funnel, KB `my-ads-internal-account`) except `not-a-website` ("See what we build").

**Sizes rendered:** 1080x1080 (feed square — the workhorse), 1080x1350 (portrait, most feed real estate), 1080x1920 (Stories/Reels, top and bottom padded for the platform's UI chrome), 1200x628 (link/landscape, also fine for Google Display). Stories are only rendered for the three strongest angles. Per-placement type `SCALE` map — landscape needed 0.8 (0.62 left dead space; the whole point of the knob).

**Design:** brand ink `#070810`, gold from `C.gold`, a gold bloom off the top-right corner + a violet counter-bloom bottom-left, a masked hairline grid for texture, a gold rule across the top, logo + brand lockup + gold kicker, one accent line in the headline, gradient CTA pill and the bare domain. No stock photography anywhere — typographic, which reproduces cleanly at every size and can't look like everyone else's stock library.

**Regenerate:** `node scripts/build-ad-creatives.js [outDir]` (needs `playwright` installed; not a runtime dep — from a sandbox, `NODE_PATH=<dir-with-playwright>`). It **fails the run if any creative overflows its canvas**, so a headline edit can't silently ship clipped. Edit `CREATIVES` for copy, `CITIES` for coverage.

**`CREATIVE_FORMAT=jpeg`** emits ad-ready JPEGs at quality 92 instead of PNGs — Meta accepts both, and the JPEG set is ~6MB against ~22MB for the same 69 PNGs with no visible banding (the designs are smooth dark gradients plus a faint grid, which dithers well). Use JPEG for anything being sent or uploaded; PNG is the lossless master. No image tooling (pngquant/optipng/Pillow) exists in this environment — Chromium's own JPEG encoder is the compression path.

## 🔴 2026-08-20 — THE CTA BUTTON WAS COVERING THE URL ON EVERY STORY

**Bryson, having seen his own live ad served to him on Instagram:** *"we need to edit the
images because the button covers the website url."*

He was right, and it was measurable rather than a matter of taste. Rendering the story
creative and reading the box positions out of the DOM:

```
hair   -> 359px clear of the bottom edge
url    -> 300px clear of the bottom edge     <-- underneath the button
```

Instagram paints its **"Learn more" CTA over roughly the bottom 250-450px** of a 1080x1920
story. The footer's baseline sat at exactly 300px, so the URL line was covered on **every
impression**.

**Cause: ONE padding value served both ends.** `padY = story ? 300` set the top and the
bottom together. The top only carries the small logo row and wants to be tight; the bottom
has a button drawn over it and needs far more. Tying them together meant the bottom could
never be right.

Now `padTop = 260` and `padBottom = 500`, which puts the footer 500px clear.

**IT AFFECTED ONLY THE 1080x1920 STORY**, which is exactly why it survived every earlier
check. Square, portrait and landscape place the CTA *underneath* the image, so their footers
were always fine, and the existing overflow guard only ever asked whether content spilled
OFF the canvas, never whether it landed somewhere unreadable. Non-story padding is
deliberately unchanged.

### 🔴 TWO RENDERERS DRAW THESE, AND BOTH HAD IT

This is the part worth remembering. They share no code:

| | |
|---|---|
| `scripts/build-ad-creatives.js` | the offline batch, 69 files |
| `index.html` (Ad Creative Studio) | **the one that actually made his live ad** |

Fixing only the script would have left the live path broken, and the live path is the one he
uses. `verify-creative-safe-zone.mjs` pins both, asserts the top and bottom stay separate
values, and was broken on each renderer independently to confirm it fails.

**Regenerate the offline set after any change here:** `NODE_PATH=/opt/node22/lib/node_modules
CREATIVE_FORMAT=jpeg node scripts/build-ad-creatives.js` (playwright is not a repo dependency,
so the global one has to be on the path). All 69 re-render with no overflow.

One assertion failed on the first run and was **my own mistake, not the code**: it searched
for the old `padY` by name and matched the comment explaining the bug. Comments are stripped
before that check now. That is the second time today a source-matching assertion has tripped
on prose.

## 2026-09-02 — the niche photo gallery (`stock-photos.mjs`)

**Bryson:** *"what if we can open a real gallery based on whatever niche I put of images that
would be good backgrounds for the ads and to be able to visually see them before I select them"*.

🔴 **What he was actually looking at was a door locked from the inside.** The "Background photo"
control listed only files ALREADY in the client's `mediaLibrary`, and the house account's library
is empty, so the control rendered with a single "None" option and offered no route to a first
photo. The gallery is the way in.

**Where it is:** Ad Creative Studio, a **Find photos for this niche** button above the dropdown.
Tap a tile and it saves and selects itself.

**The query matters more than the niche.** `searchTerms()` appends `professional at work`, because
"roofing" alone returns diagrams and stock icons while "roofing professional at work" returns
photographs of a job in progress. An empty niche falls back to `small business owner working`
rather than an empty query, since the first press usually happens before he has typed a niche.

### 🔴 Why a chosen photo is COPIED, not linked

The creative is drawn on a `<canvas>` and read back with `toBlob()`. **Drawing a cross-origin
image taints the canvas and the read back throws**, so a linked photo would preview perfectly and
then fail at download, which is the worst possible place to discover it. Copied into our own
Supabase bucket it is indistinguishable from an upload: same bucket, same public URL, same
`category:"photo"` (which the launch card, the landing renderer AND the studio all filter on, so
any other value files it where nothing looks), same delete button, and it survives Pexels moving
the file.

### 🔴 The host allow list is a security control

`action=save` makes the **server** fetch a URL the **browser** chose. Without a check on where that
URL points, anyone holding a session could aim it at an internal address and read the response back
out of the media library afterwards.

Only `images.pexels.com`, checked on the **parsed hostname**. Not a substring match:
`https://evil.com/images.pexels.com/x.jpg` and `https://images.pexels.com@evil.com/x.jpg` both
defeat the naive version and both are in the test. https only. The response content type must
start with `image/`. Off-host photos are also dropped at SEARCH time, so a tile that could never be
saved is never shown.

### Setup

**`PEXELS_API_KEY`** in Netlify on the **`boldlinemedia`** site (no hyphen). Free, no card.
Get it at pexels.com/api. Without the key the function answers in plain words rather than failing
obscurely, and that message is the whole instruction Bryson gets, so it names Netlify.

### Testing notes

15 checks, six mutations, all caught. 🔴 **Two escaped a first pass**, both the usual lesson:
the gating check only matched a gate sitting IMMEDIATELY before the button, so a real mutation that
opened it a few lines earlier walked past; and the fixed version then failed on the CLEAN file
because the comment above the button explains that it is deliberately not gated on `photos.length`,
and the check read its own prose as the rule. **Comments are stripped from the window first**, the
same fix `verify-app-boots` already carries.

### Standing judgement, unchanged

The typographic creatives stay the default. Stock photography is how an ad ends up looking like
every other agency's. The gallery exists because a real photo reads as less of an ad in the Meta
feed specifically, so it is for selective use, not for everything.
